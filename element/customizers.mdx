---
title: "Product customizers"
description: "Share a product page with a design tool, so shoppers can either upload a finished file or design one, and Add to cart works for both."
---

Some product pages offer two ways to buy: upload a finished file through Filecheck, or design one in a product customizer. Without coordination, each tool gates **Add to cart** on its own, so each blocks the shopper who chose the other.

When the Element runs its own cart gate (the store plugins, or `Filecheck.mount`), it owns **Add to cart** for both. A customizer tells it when the shopper's design is in, through three `window` events. Nothing else is shared: each tool keeps its own cart fields.

<Note>
  Print.App uses these events. Any other customizer can use them the same way.
</Note>

## How Add to cart behaves

| The customizer requires a design | The upload is required | Add to cart is enabled when |
|---|---|---|
| no | no | always |
| yes | no | a design is in, or a file passed |
| no | yes | a file passed, or a design is in |
| yes | yes | a file passed, or a design is in |

The last thing the shopper did owns the cart line:

- **Designed last:** the Element resets the upload, so its job leaves the cart form. The customizer's message shows under the upload box.
- **Uploaded last:** once the file passes, the Element tells the customizer, which removes its own design from the cart form.

Only the file that will be printed reaches the order.

## The events

All three are `CustomEvent`s on `window`, with their data in `detail`.

### `filecheck:ready` (Element to page)

```js
{ version: 1, gate: true, status: { status, canProceed, jobId, filesIn } }
```

Sent when the Element mounts, and again when a customizer it has not heard from speaks up. When a customizer hears it, the Element owns Add to cart: stop hiding or disabling the button yourself.

### `filecheck:alternative` (customizer to Element)

```js
{ source: 'my-customizer', done: true, required: true, message: 'Using your design.' }
```

| Field | Type | Meaning |
|---|---|---|
| `source` | string | A stable id for your customizer: letters, digits, `_ . : -`, up to 64 characters. |
| `done` | boolean | The shopper's design is in the cart form. |
| `required` | boolean | Optional. Your own "a design is required" setting. |
| `message` | string | Optional. Shown under the upload box while the design owns the line, in your own language (up to 300 characters). |

Send it once on start, since the Element may already be on the page, and again whenever `done` changes.

### `filecheck:status` (Element to page)

```js
{ status: 'ready', canProceed: true, jobId: 'job_…', filesIn: true }
```

Sent on every upload status change. `filesIn: true` means a file passed and now owns the line: remove your design from the cart form, then send `done: false`.

## Example

```js
const SOURCE = 'my-customizer';
let designIn = false;
let filecheckGates = false;

const tell = () => window.dispatchEvent(new CustomEvent('filecheck:alternative', {
  detail: { source: SOURCE, done: designIn, required: true, message: 'Using your design.' },
}));

window.addEventListener('filecheck:ready', () => {
  filecheckGates = true;   // stop gating Add to cart yourself
  showAddToCart();
  tell();
});

window.addEventListener('filecheck:status', (e) => {
  if (e.detail.filesIn && designIn) {
    removeDesignFromCartForm();   // your own fields only
    designIn = false;
    tell();
  }
});

onDesignSaved(() => { designIn = true; tell(); });
onDesignRemoved(() => { designIn = false; tell(); });

tell();   // the Element may already be there
```

## When it doesn't apply

- **The Element mounted by your own code** with `Filecheck(...)`: there is no built-in cart gate, so no `filecheck:ready` is sent. Your page decides Add to cart.
- **A page builder or options app that owns Add to cart itself** (Print.App's Print Options, for example): it already combines both tools, and the Element's own gate is not used.
